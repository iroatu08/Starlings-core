This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Starlings Hospitality — a travel booking platform. Monorepo with two independent apps, each with its own `package.json` and dependency tree:

- `backend/` — Node.js + Express + Prisma + PostgreSQL REST API
- `frontend/` — React 18 + Vite + TypeScript SPA

There is no root package.json / workspace tool; run commands from within each app directory.

## Commands

### Backend (`backend/`)

```bash
npm run start:dev            # ts-node-dev with watch mode (default dev command)
npm run build                 # tsc + copies mail/templates/*.hbs into dist/
npm start                     # node dist/server.js (prod)
npm run lint                   # eslint --fix
npm test                       # jest unit tests (all *.spec.ts under src/)
npx jest path/to/file.spec.ts  # run a single test file
npm run prisma:pull             # introspect the DB into prisma/schema.prisma
npm run migration:generate -- <name>  # prisma migrate dev --create-only --name <name>
npm run migration:run:dev        # prisma migrate dev (local, applies + may prompt)
npm run migration:run             # prisma migrate deploy (non-interactive, used in deploy:build)
npm run seed                       # prisma db seed → prisma/seed.ts
```

Local Postgres is provided via `backend/docker-compose.yml`. Config is validated at boot by a Joi schema in [env.ts](backend/src/config/env.ts) — the app will fail to start (`process.exit(1)`) if a required env var is missing (see `backend/.env.example` for the full list: JWT secrets, `DATABASE_URL`, Resend, Paystack, Cloudinary, `ADMIN_EMAIL`). `.env` is loaded via `dotenv/config` imported at the top of `env.ts`.

Prisma schema lives at `backend/prisma/schema.prisma`, generated by introspecting the real DB (`prisma db pull`) and then hand-cleaned to PascalCase models with `@map`/`@@map` back to the original snake_case tables/columns — keep that mapping intact if you edit the schema by hand rather than re-pulling. Migration history was baselined from the pre-existing DB state (`prisma/migrations/0_init`, applied via `migrate resolve` rather than actually run) — new schema changes should go through normal `prisma migrate dev`.

### Frontend (`frontend/`)

```bash
npm run dev        # vite dev server
npm run build       # tsc && vite build
npm run lint        # eslint, zero warnings allowed
npm run preview
```

Env vars: `VITE_API_URL`, `VITE_PAYSTACK_PUBLIC_KEY` (see `frontend/.env`).

## Architecture

### Backend — Express module-per-domain, Prisma for data access

Each domain under `backend/src/modules/` is a self-contained folder (`routes.ts`, `*.service.ts`, `schemas.ts`) mounted in [server.ts](backend/src/server.ts): `auth`, `users`, `destinations`, `packages`, `cart`, `bookings`, `payments`, `gallery`, `contact`, `newsletter`, `reviews`, `admin`, `mail`. There is no DI container — services are plain exported async functions that import the shared `prisma` client directly; routes call them and reply via `res.success(data)`.

Domain model (see [schema.prisma](backend/prisma/schema.prisma)): a `Destination` (country, hero image, geo coords) has many `Package`s (visa/hotel/taxi/transfer/custom, priced in NGN + USD). A `Booking` belongs to a `User` and has many `BookingItem`s and `BookingTraveler`s, one `Payment`, and possibly `RefundRequest`s. `Cart`/`CartItem` hold pre-checkout selections, including a `bundleSnapshot` JSON column (typed via [bundle-snapshot.ts](backend/src/types/bundle-snapshot.ts)) capturing which packages in a destination bundle were kept/removed and at what price, at the time of adding to cart or booking.

Auth: JWT access + refresh tokens (HS256), signed with `jsonwebtoken` directly (no Passport). Access token returned in the login response body and sent as `Authorization: Bearer`; refresh token set as an `httpOnly` cookie (`refresh_token`) and its bcrypt hash stored on the `User` row. Middleware: `requireAuth` / `requireRefreshCookie` ([auth.ts](backend/src/middleware/auth.ts)) for authentication, `requireRole(...)` ([roles.ts](backend/src/middleware/roles.ts)) for authorization (checks `UserRole.admin`/`user`) — see [auth.service.ts](backend/src/modules/auth/auth.service.ts).

Cross-cutting concerns wired in [server.ts](backend/src/server.ts): `helmet()` (relaxed CSP scoped to `/api/docs*` so Swagger UI renders, strict everywhere else), `cookie-parser`, CORS via `resolveCorsOrigins()` ([cors-origins.ts](backend/src/config/cors-origins.ts), reads `ALLOWED_ORIGINS` or falls back to `FRONTEND_URL`), `express-rate-limit` (global 100/min, plus a stricter 10/min on `/auth`), zod-based `validateBody`/`validateQuery` middleware ([validate.ts](backend/src/middleware/validate.ts)) replacing class-validator DTOs, a `responseEnvelope` middleware attaching `res.success(data)` (wraps responses as `{success, data, timestamp}` — the frontend axios client expects `response.data.data`), and a final `errorHandler` ([error-handler.ts](backend/src/middleware/error-handler.ts)) that catches thrown `AppError` subclasses ([app-error.ts](backend/src/utils/app-error.ts): `BadRequestError`, `UnauthorizedError`, `ForbiddenError`, `NotFoundError`, `ConflictError`) and formats `{success:false, statusCode, message, timestamp, path}`.

API docs: OpenAPI 3 spec is hand-registered in [openapi/document.ts](backend/src/openapi/document.ts) using `@asteasolutions/zod-to-openapi`, reusing the same zod schemas each route validates against — update a route's `schemas.ts` and its docs stay accurate; add new routes to `document.ts` manually (there's no decorator-based auto-discovery). Served at `/api/docs` (Swagger UI) and `/api/docs-json` (raw spec).

Payments: Paystack integration in `payments/` (initialize, webhook signature verification via `PAYSTACK_WEBHOOK_SECRET` — HMAC-SHA512 over `JSON.stringify(req.body)`, refund requests). Email: `mail/` uses Resend's HTTP API (not SMTP) with Handlebars templates in `mail/templates/*.hbs` (copied into `dist/` by the build's `copy-templates` step), rendered by `template-renderer.ts`. Uploads: Cloudinary via `multer` memory storage (`gallery/`, `admin/routes.ts`'s `/gallery/upload`).

Migrations live in `backend/prisma/migrations/`. The `0_init` migration is a baseline (marked applied via `prisma migrate resolve`, not actually run) representing the schema as it existed before this Prisma migration; write new migrations the normal way (`prisma migrate dev --name ...`) going forward.

### Frontend — feature-oriented React SPA

- `pages/` — route-level components, all lazy-loaded in [router/index.tsx](frontend/src/router/index.tsx) with `AnimatePresence` page transitions. Split into public pages, `pages/dashboard/*` (authenticated user area) and `pages/admin/*` (admin panel), each with their own layout route.
- `features/<domain>/` — hooks encapsulating a domain's client-side logic (`useAuth`, `useCart`, `useBookings`, payment hooks under `features/payment/`).
- `api/*.api.ts` — one file per backend module, thin wrappers around the shared `apiClient` (axios instance).
- `stores/` — Zustand stores (`authStore`, `cartStore`, `uiStore`) for global client state.
- `components/shared/`, `components/admin/`, `components/home/`, `components/ui/` — presentational components grouped by scope.
- Route protection: `<AuthGuard>` wraps authenticated routes, `<AdminGuard>` wraps `/admin/*` (both in `features/auth/`).

Auth token flow: [axios.client.ts](frontend/src/api/axios.client.ts) attaches the access token from `authStore` to every request, and on a 401 (excluding login/register/refresh/password endpoints) transparently calls `POST /auth/refresh` (cookie-based) once, queues concurrent requests during the refresh, retries with the new token, and force-redirects to `/login` if refresh fails — except on already-public auth pages.

Styling: Tailwind CSS (`tailwind.config.ts`, `styles/globals.css`) with a "navy / off-white / slate" brand palette used throughout class names; `framer-motion` for transitions; Radix primitives for dialogs/dropdowns/select/tabs/toast.
